# FATHER CODEX — Programmer Coach / Тренер программиста

**Версия:** 1.0, 2026-11-25  
**Статус:** ARCHITECTURE_PROPOSED / CURRICULUM_DESIGNED / NOT_IMPLEMENTED / NOT_QUALIFIED  
**Связи:** FATHER AI Academy, FATHER_CODEX Senior Engineering Agent, ALINA Knowledge Worker, FATHER IDEA+, Cost Engineering, POLYGON.

## 1. Миссия

Не писать вместо ученика, а **развивать его способность самостоятельно** понимать задачу, выбирать алгоритм, проектировать ПО, писать корректный код, проверять, оптимизировать, защищать, внедрять и объяснять инженерные решения.

**Целевая траектория:** BEGINNER -> JUNIOR -> MIDDLE -> SENIOR. Уровень подтверждается выполненными работами и независимыми заданиями, а не количеством уроков, сертификатом или субъективным впечатлением LLM. «Senior» как рыночная квалификация включает практический производственный опыт, взаимодействие с людьми и ответственность за последствия — один учебный экзамен не присваивает стаж и должность.

## 2. Три роли — не смешивать

1. **Student Programmer:** самостоятельно предлагает алгоритм, пишет код, задаёт вопросы, объясняет решение.
2. **FATHER CODEX Senior Reviewer:** исследует альтернативные алгоритмы/архитектуры, выполняет контролируемый review/refactoring/optimization, обосновывает изменения ссылками и бенчмарками. Не подменяет деятельность ученика.
3. **Programmer Coach:** оценивает текущие компетенции, строит персональную программу, задаёт наводящие вопросы, открывает помощь постепенно, выбирает упражнения и диагностирует устойчивые ошибки.
4. **POLYGON Examiner:** отдельно генерирует и хранит закрытые проверки, оценивает результат и готовит evidence. Тренер не должен видеть закрытые эталоны и не может сам ставить финальный PASS.

## 3. Матрица развития компетенций

| Компетенция | JUNIOR | MIDDLE | SENIOR |
|---|---|---|---|
| Постановка задачи | Пересказывает вход/выход | Формализует контракты и крайние случаи | Оценивает требования, ограничения и альтернативы |
| Алгоритмы | Циклы, словари, поиск, базовая сложность | Графы, сложные структуры, выбор по нагрузке | Доказательный выбор по workload; компромиссы и профилирование |
| Python и языки | Синтаксис, функции, типы, ошибки | Пакеты, typing, async, тесты, SQL | API/ABI/contracts, concurrent failure modes, совместимость |
| Рефакторинг | Убирает дублирование | Контролирует сохранение поведения | Отделяет изменения поведения от структуры, управляет миграциями |
| Тестирование | Unit и edge cases | Интеграция, property-based, CI | Контракты, негативные тесты, test strategy, observability |
| Архитектура | Простые модули | Компоненты, зависимости, API | ADR, эволюция систем, доступность, отказоустойчивость |
| Безопасность | Работа с секретами и вводом | Threat modeling, least privilege | Security architecture, trade-offs, audit/evidence |
| Экономика | Время/память программы | CPU, RAM, токены, облако | TCO, capacity, ROI, cost per qualified outcome |
| Коммуникация | Объясняет код | Code review и документация | Защищает решение, наставляет, управляет рисками |
| Эксплуатация | Запускает локально | CI/CD, контейнеры, диагностика | SLO, incident response, rollback, observability |

**Не каждый senior обязан знать все языки/фреймворки.** Уровень определяется автономностью и доказанной компетенцией в выбранном профессиональном профиле.

## 4. Обучающий цикл

```text
Diagnostic (без подсказок)
  -> Competency Graph (skills, prerequisites, evidence, confidence)
  -> Personal Learning Plan (цели, baseline, время, стоимость)
  -> Learn (понятная теория, алгоритм, оригинальные примеры)
  -> Practice (сначала самостоятельное решение)
  -> Progressive Hints (вопрос -> указание на ошибку -> фрагмент -> эталон)
  -> Code Review (без раскрытия скрытого экзамена)
  -> Compare implementations and benchmarks
  -> Spaced repetition + transfer tasks
  -> Independent POLYGON challenge
  -> Update competence graph / next stage
```

Помощь по умолчанию минимальна. Ученик всегда может запросить объяснение. Для объективного экзамена подсказки отключаются и учитывается происхождение решения.

## 5. Источники и программа

- Стартовый учебный материал: Antonio Gulli, *Agentic Design Patterns*, CH01–CH07: цепочки, маршрутизация, параллелизация, рефлексия, инструменты, планирование и сотрудничество.
- **Algorithm Knowledge Base:** проверяемые алгоритмы, история решения, постановка задачи, предусловия, сложность, код, источники и лицензии.
- **Language Knowledge Base:** Python первоначально, затем выбранные языки. Руководства и спецификации версионируются.
- **Engineering Knowledge Base:** проектирование, тесты, SOLID как инструмент, а не догма, безопасность, DevSecOps, FinOps, устойчивость.
- ALINA управляет источниками, достоверностью и графом знаний. Сторонние книги не публикуются целиком без права.

## 6. Уровни заданий на одном примере (CH02 Routing)

1. **Beginner:** исправить условия `if`, распознать команду.
2. **Junior:** написать функции, типы, тесты для отрицательных случаев.
3. **Middle:** разделить router/policy/dispatcher, оформить контракт, обеспечить покрытие и читаемые ошибки.
4. **Senior track:** определить границы доверия, администрирование правил, версионирование, отказоустойчивость, метрики, нагрузку, стоимость, альтернативы, ADR, план миграции и доказательную приёмку.

Не путать синтаксически сложное решение с профессионально лучшим: выбирать самый простой алгоритм, удовлетворяющий требованиям.

## 7. Устройство агентов

```text
FATHER IDEA+ -> Academy Curriculum -> Coach / Diagnostician
                     |                |
                     v                v
          Algorithm/Language KB <- Competency Graph
                     |                |
                     +----> Practice Sandbox
                                 |
                     Student solution + tests
                                 |
                  FATHER CODEX Senior Reviewer
                                 |
                      Guided comparison / ADR
                                 |
                      POLYGON (isolated exams)
                                 |
                    Evidence-based progression
                                 |
                  Dashboard (RU/EN, consent-first)
```

Coach должен отделяться от Code Reviewer, Executor, Knowledge Store и Examiner; права на запуск кода только у sandbox, с ограничениями CPU, memory, time, filesystem, network and secrets.

## 8. Проверка компетенции

- Решение новой задачи без подсказок и с ограничением времени.
- Обоснование применённого алгоритма, его сложности и граничных случаев.
- Негативные, property-based, интеграционные тесты и защита от регрессии.
- Ревью чужого кода и объяснение исправлений.
- Изменение требований по ходу задачи и безопасная модификация.
- Диагностика производительности, безопасность, стоимость эксплуатации.
- Для senior track — проектное решение с ADR, рисками, эксплуатационной моделью, альтернативами и внешней защитой.

**Показатели:** skill mastery by evidence, independent task success, hint dependency, retention after delay, transfer to new tasks, code quality metrics, execution costs. Нельзя выдавать «прогресс» только по количеству задач или красивым ответам LLM.

## 9. Продуктовая линейка

- **School 12–17:** визуальные блоки, алгоритмы без LLM, практика и игры; без регистрации и персональных данных в публичном MVP.
- **Professional Programmer:** Python и реальные проекты от junior до senior.
- **Corporate/Team Track:** практика review/architecture/DevSecOps на синтетических и разрешённых корпоративных примерах.
- Интерфейс русского и английского языков; публичный сайт не содержит закрытых тестов, личных данных, секретов, ключей и приватного кода.

## 10. Порядок реализации

P0: корпус задач CH01–CH07 с простыми корректными Python baseline и unit tests.  
P1: единая schema `Skill, Exercise, Attempt, Hint, Review, Evidence, ExamResult`.  
P2: детерминированный тренер для CH01, затем CH02; проверяем обучение без модели.  
P3: подключить ALINA retrieval и FATHER CODEX Reviewer как помощника; зафиксировать источники.  
P4: sandbox для выполнения разрешённого кода; безопасный inference adapter с лимитами.  
P5: POLYGON independent skill exams; измерение удержания навыков.  
P6: визуальные страницы курса, динамический граф компетенций и расходы на обучение.  

**Первый acceptance gate:** на CH01 ученик собирает цепочку, пишет простой Python pipeline без готового ответа, объясняет порядок шагов и проходит новую задачу с отрицательным сценарием; результаты подтверждены независимыми тестами. Пока такой экзамен не проведён.

## 11. Архитектурные и юридические ограничения

Всё по FATHER baseline: human commits, ADR, data/component/security/qualification contracts, SHA-256 provenance, evidence, signed releases по установленной процедуре, SBOM. Consent-first learning analytics; минимизация детских данных. Никаких притязаний на фактический уровень senior без профессионального доказательного опыта и внешней оценки.
