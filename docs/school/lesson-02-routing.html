Глава 2 · Routing / Маршрутизация

Школа агентов: умный диспетчер

Представь штаб из нескольких помощников. Кто должен отвечать на вопрос? Научим программу выбирать исполнителя и узнаем, почему ошибаться может даже умная модель.

Теория → примеры → симулятор → ошибки → экзамен
01 · Понимание

Что такое маршрутизация?

Маршрутизация — выбор следующего пути выполнения по условию. Диспетчер получает запрос, определяет его тип и направляет к подходящему исполнителю. Он не обязан сам выполнять задачу.

ВопросЧто нужно сделать?
→
ДиспетчерВыбирает путь
→
СпециалистВыполняет действие
Сравни с главой 1. Цепочка выполняет шаги последовательно. Router выбирает одну из ветвей в зависимости от входа или текущего состояния.
02 · Вся основная теория

Четыре способа выбора маршрута

1. Правила (Rule-based)

Условия if/else и заранее заданные правила. Простые, быстрые, проверяемые, но плохо понимают необычные формулировки.

if "посчитай" in text: route = "math"

2. Языковая модель (LLM)

Модель получает запрос и возвращает название категории. Гибче, но может ошибаться, требует проверки ответа и расходует ресурсы.

LLM("Определи класс") → "translator"

3. Смысловые векторы (Embedding)

Вопрос и категории превращаются в числовые представления. Система сравнивает их близость. Похожий смысл не гарантирует правильный выбор.

vector(query) → similarity → closest_route

4. Обученный классификатор (ML)

Специальную модель заранее обучают на размеченных примерах, затем она выбирает класс без генерации текста во время решения.

classifier.predict(query) → "math"

Что должен понимать инженер

Неизвестная задачаЕсли маршрут непонятен — попросить уточнение, а не угадывать.
КонфликтОдин запрос может содержать несколько намерений; нужны правила приоритета или уточнение.
БезопасностьВыбор инструмента не означает разрешение его запускать. Проверка прав — отдельно.
03 · Интерактивная лаборатория

Проверь своего диспетчера

Выбирай пример или вводи свой текст. Симулятор использует простые правила и не обращается к LLM, поэтому не передаёт запрос в облако.

Маршруты

∑ МатематикСчитает
文 ПереводчикПереводит
✦ СправочникОбъясняет
Ожидаю запрос. Пока ничего не выполнялось.
Справочник, переводчик и математик здесь — условные исполнители. Симулятор только показывает выбор пути; он не переводит и не бронирует ничего по-настоящему.
04 · Сломай систему

Найди слабое место

Диспетчер маршрутизирует только по ключевому слову «посчитай». Куда попадёт фраза «Сколько будет 8 × 9?»

Результат появится здесь.

Подумай: что лучше — добавить ещё одно правило, использовать обученный классификатор или спросить уточнение?

Единственного ответа нет. Решение зависит от количества разных запросов, допустимой цены ошибки, скорости и стоимости обработки.

05 · Экзамен без подсказок

Проверяем понимание теории

Три вопроса. После ответа показываем объяснение. Для завершения нужно решить новую задачу самостоятельно.

Задание на перенос знаний

Есть три агента: проверяющий код, переводчик и исследователь. Пользователь пишет: «Проверь Python-функцию и найди возможные ошибки». Каким должен быть маршрут, что делать при неясности и как проверить результат?

Ответьте письменно или расскажите вслух. Обязательно объясните, почему выбран маршрут. Автоматической проверки этого открытого ответа пока нет — нужен преподаватель или независимый экзаменатор.

06 · Первый Python-код

Тот же алгоритм на Python

def route(text: str) -> str: text = text.casefold() matches = [] if "посчитай" in text: matches.append("math") if "переведи" in text: matches.append("translate") if "объясни" in text: matches.append("info") if len(matches) == 1: return matches[0] return "clarify" assert route("Посчитай 5 + 7") == "math" assert route("Посчитай и переведи") == "clarify" assert route("Помоги!") == "clarify"
