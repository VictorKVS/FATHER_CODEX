# FATHER Academy — обязательный формат дальнейших уроков CyberED

**Дата утверждения для учебного workflow:** 2026-11-27. **Статус:** DOCUMENTED_PROCESS / NOT_AUTOMATED.

Для каждого **нового загруженного пользователем** файла лекции выполнять в ходе текущего запроса и явно разделять три независимых слоя.

## A. Оригинальная лекция CyberED — доказательный разбор

1. Верифицировать `format / duration / audio / video`; извлечь временные точки и слайды.
2. Если доступна ASR — получить `SRT / VTT / TXT` с временными метками, пометить `ASR_DRAFT`, исправить термины, имена и отрицания по прослушиванию; только выверенное помечать `AUDIO_VERIFIED`. Если ASR недоступна, **не придумывать дословную речь**.
3. Для каждого утверждения различать `DIRECT_SLIDE`, `AUDIO_VERIFIED`, `AUTHOR_EXPLANATION`, `EXTERNAL_SOURCE`, `INFERENCE`, `UNCERTAIN`.
4. Сохранить таймкоды и источник, указать границы увиденного и не увиденного. Полные чужие видеозаписи не публиковать в открытом репозитории.

## B. Инженерный учебник и вопросы для собеседования

1. Суть на 30 секунд, базовые определения, словарь, роли и связи.
2. Разбор исходных схем/алгоритмов и проверка противоречий по официальным источникам.
3. Точные ссылки на стандарт / раздел / редакцию; различать рекомендации и обязательные требования по применимости.
4. Кейсы для Junior, Middle, Senior, Security Architect и TIMA / ALINA / POLYGON.
5. Типичные ошибки, отрицательные тесты, контрольные вопросы, решения и доказательства.
6. Отмечать статусы `REGISTERED`, `EXPLAINED`, `TESTED`, `QUALIFIED` без ложного повышения.

## C. Собственная авторская лекция FATHER (около 20 минут)

1. Оригинальная последовательная речь с временной разметкой на ~20 минут.
2. Объяснение простым языком + точные инженерные нюансы + сценарий из FATHER.
3. Маркеры `[ОБЯЗАТЕЛЬНО ВЫУЧИТЬ]`, `[СОБЕСЕДОВАНИЕ]`, `[ПРАКТИКА]` по необходимости.
4. Выделять от исходной лекции: это независимое авторское изложение, **не транскрипт CyberED**.
5. Новая страница в `docs/school/`; авторский текст в `docs/school/lectures/`; навигация в `docs/school/index.html` и программе S-235.
6. Критерии готовности — содержимое и ссылки присутствуют в GitHub; если интерактивность не проверена браузерным тестом, состояние `UI_NOT_QUALIFIED`.
7. Пользователь сам синхронизирует локальный репозиторий `git pull --ff-only`. Автономная обработка **без нового пользовательского запроса или подключённой автоматизации не выполняется**.
