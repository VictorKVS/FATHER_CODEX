# FATHER Test Factory — архитектура испытаний и доказательств

**Version:** 0.1.0 • **Date:** 2026-11-28 • **Status:** ARCHITECTURE + EXECUTABLE CATALOG VALIDATOR (NOT A SECURITY CERTIFICATION)

## Назначение
Единый механизм проектирования, подготовки, исполнения и документирования испытаний для FATHER_CODEX, SADEQ, ALINA, RAG, UAG и остальных специализаций. **Проверяем не только то, что система делает, но и что она обязана НЕ делать.** Это общий инженерный сервис; не заменяет независимый POLYGON и не копирует его экзаменационные наборы.

## С чего начинаем
1. [Структура и границы системы](docs/ARCHITECTURE.md) — ядро, адаптеры, доверенные границы.
2. [Библиотека книг и стандартов](docs/BOOKS_AND_STANDARDS.md) — точное сопоставление первоисточников с методами испытаний.
3. [Контракты и критерии допуска](docs/CONTRACTS_AND_GATES.md) — машиночитаемые паспорта, статусы, evidence.
4. [Дорожная карта](docs/MVP_ROADMAP.md) — от каталога до рабочего orchestration и POLYGON.
5. [Первая методика испытаний](catalog/cases/SADEQ_API_001.json) — **проект** сценария BOLA/tenant isolation, ссылки на действующий проект ПМИ SADEQ.
6. [Схема процесса](diagrams/TEST_FACTORY_PIPELINE.mmd).

## Что уже реализовано и проверяется
- Машиночитаемый каталог сценариев и источников, JSON Schema Draft 2020-12 как нормативная модель данных (`schemas/test_case_v1.schema.json`).
- Небольшой Python-валидатор **части критических инвариантов каталога** (без сторонних библиотек), который отвергает незнакомые поля, неразрешённые источники, пустые MUST NOT и отсутствие признаков доказательств.
- CLI проверки паспортов и явный блокирующий режим `--release`.
- Unit-тесты самого валидатора (не являются тестами защищённости SADEQ).

## Что НЕ реализовано
- Полный валидатор всех JSON Schema ключей, lint методик ГОСТ, полноценный сбор source evidence.
- Запуск pytest / Semgrep / Trivy / ZAP / fuzz / agent eval через изолированные workers.
- Подписанные/SBOM attestations, неизменяемое evidence storage, RAG/knowledge graph источников, CI pipeline, UI.
- Независимое исполнение POLYGON и приёмочная комиссия.

## Проверка на Python 3.12+
```powershell
cd G:\1\FATHER_CODEX\quality\test_factory
py -3.12 -m unittest discover -s tests -v
py -3.12 scripts\validate_cases.py
py -3.12 scripts\validate_cases.py --release
```
`--release` на этом этапе **должен вернуть ненулевой код**: паспорт API-001 пока DRAFT и не имеет проверенных execution evidence / signoff.

## Корпоративная схема
`Источник/книга → локатор/пункт → требование → модель угроз → методика ПМИ → сценарий TEST → исполнитель → наблюдения → EVIDENCE SHA256 → заключение POLYGON → решение человека`.

**Юридически:** книги пользователя служат справочной основой; тексты книг и нелицензированные выдержки не публикуем. ГОСТы применяем в пределах их действительной области применения. Наши требования могут быть строже стандарта, но не выдаются за его дословные предписания.
